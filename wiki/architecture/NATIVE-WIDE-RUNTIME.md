# Native Wide Runtime Integration

Publish raw word, exact value, typed operation and display/status catalogues in
Backend.Runtime.Integer dependency order. Its dependency function combines all
catalogues with the existing scalar dependencies. A selected fail renderer owns
site, colored and cleanup prerequisites; do not rely on every caller inserting
them. Existing narrow generated programs retain their runtime layout and output.
Frame ABI revision remains 5 until the following wide-frame integration.

Wide.Display exports wideDisplayRuntimeParts and wideDisplayRuntimeDependencies.
wide_print_int normalizes zero, obtains magnitude and repeatedly divides by ten
into a fixed 41-byte stack buffer, including optional sign and newline. Emit
one fwrite and flush, with no heap, locale or host 128-bit extension. Magnitude
is at most 39 digits; the longest sign/digits/newline occupies 41 bytes. Actual
sign is independent of the high bit. wide_status returns zero for zero, one
for negative values, otherwise clamps the full two-word positive value to 255.
These match existing scalar printing/status policies; owned text/IO Result and
public Int128/UInt128 admission remain later obligations.

Backend Engineer owns Wide.Display, Runtime.Integer and library registration.
Test Engineer owns WideRuntimeSpec, suite registration and matching mirrors.
Execute full-width signed/unsigned/deferred and transient-zero display/status
cases against independent Integer answers. Compile every wide primitive root
against the actual Runtime catalogue and execute a real E7005 renderer path,
proving diagnostic prerequisites without the previous failure stub. Use strict
C11, Clang/GCC, ASan/UBSan and full gates. Independent review/platform evidence
remain required before promotion. No subagents execute.

## Resolved Grill Log

- **Q:** Let callers remember colored and cleanup? **A:** No; fail owns all renderer prerequisites.
- **Q:** Print only the low word? **A:** No; decimal conversion consumes the full magnitude.
- **Q:** Use a locale-sensitive or compiler-specific formatter? **A:** No; bounded decimal digit construction uses the portable word kernel.
- **Q:** Treat a high unsigned bit as negative? **A:** No; both output/status follow actual sign.
- **Q:** Admit source types or bump frame ABI now? **A:** No; the following frame/admission deliveries retain those obligations.
