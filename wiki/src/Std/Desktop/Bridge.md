# Std Desktop Bridge

## Purpose and interface

The page-side bridge every view receives: `script(key, label, dev)` is the injected source applied to
the view's configuration; `declarations()` is its TypeScript surface (`PuduBridge`, `PuduError`,
`Channel`, `PuduEvent`).

## Semantics

- Generated by `scripts/desktop-bridge.mjs` from `tools/pudu-js/bridge.js` and `bridge.d.ts`; the
  gate runs the generator with `--check`, so the module cannot drift from the tested sources.
- The bridge installs a frozen, non-configurable `window.__pudu` once; the invoke key lives only in
  its closure.
- In development it forwards `console.error`, `console.warn`, uncaught errors and unhandled
  rejections to the reserved `pudu:console` command with their source position.

## Grill Log

- **Q:** Why generate the module rather than write JavaScript in a Pudu string? **A:** A string
  literal interpolates braces, so hand-escaped JavaScript is unreadable and untestable. The source
  of truth stays a JavaScript file tested under Node ([[Pudu JS Bridge Test]]).
