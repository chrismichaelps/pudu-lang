# Pudu Version

## Purpose

Provide canonical package and language version reporting derived directly from Cabal
package metadata, generate compatible minor-version language constraints, and evaluate
version constraints declared in project manifests.

## Interface

### Signatures

```haskell
versionText :: Text
languageConstraint :: Text
acceptsLanguage :: Text -> Either Text Bool
```

- `versionText` exposes the active package version as text (e.g. `"0.1.0"`), sourced directly
  from autogenerated `Paths_pudu.version`.
- `languageConstraint` generates the standard upper-bounded semver constraint clause for the current
  series (e.g. `">=0.1.0 <0.2.0"`), used by project templates during `pudu init`.
- `acceptsLanguage` parses one or more space-separated comparison clauses (`>=`, `<=`, `>`, `<`, `=`, `==`)
  and tests whether the active compiler version satisfies all constraints.

### Governance

- The Cabal package manifest is the sole authority on version numbers. Version strings must
  never be duplicated or hardcoded across Haskell modules or CLI tools.
- Version comparisons support up to four numeric components (`major.minor.patch.build`). Missing
  trailing components are padded with zeroes.
- Empty or malformed version constraint strings return a descriptive `Left Text` error.

### Linkage

- **Requires:** `Paths_pudu` (Cabal build metadata).
- **Consumed by:** [[Pudu CLI]], [[Pudu REPL]], [[Compiler Program]], [[Language Server]].

## Algorithm

Split constraint text on whitespace. For each clause, extract the comparison operator and version
numbers. Parse numeric components with overflow checks. Pad both the current compiler version and
the candidate version to equal width and apply the relational operator. Return `Right True` only if
all clauses evaluate to true.

## Negative Logic (Prohibited Paths)

- No hardcoded fallback version numbers.
- No network requests or dynamic manifest parsing for the compiler's own version.
- No unhandled exceptions during constraint evaluation: parsing failures return explicit errors.

## Grill Log

- **Q:** Why derive the version from Cabal rather than a constant in source?
  **A:** Hardcoded versions drift across releases, packaging scripts, and Cabal manifests.
  `Paths_pudu.version` is generated directly by Cabal at build time from `pudu.cabal`.
- **Q:** Why enforce semver constraints in `Compiler.Program` rather than the CLI driver?
  **A:** All entry points (CLI `check`, `run`, REPL `:load`, LSP server) must uniformly respect
  manifest language constraints.

## Source digest (#352)

- `sourceDigest` is the SHA-256 [[Version Digest]] spliced in at compile time over the compiler's
  sources; `identityText` is `version+digest`, the name a bundle's products are filed under.
- `digestIn bytes` finds the literal `PUDU-SOURCE-DIGEST:` + 64 lowercase hex + `;` in an
  executable's bytes, skipping malformed candidates; its own needle is assembled from two pieces so
  it never matches itself.
