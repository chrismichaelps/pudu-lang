# Deep Renderer Fixture

## Purpose and interface

Builds HTML and JSON values, and two UI trees, beyond the nesting that previously exhausted the
evaluator's call frames. Its `main` returns an exact assertion count consumed by the service
evaluation spec.

## Governance and algorithm

Values are built in loops rather than decoded or generated by host code, so the fixture exercises
the public Pudu constructors and the ordinary evaluator. HTML checks exact compact length and edge
markup. JSON checks both compact and pretty output. UI checks the one deep text edit, its exact path
depth, the rendered result after applying it, and a path that walks the full depth before naming a
missing child. Assertions avoid recursive equality of the deep values so the contract under test is
specifically rendering, comparison, and patch application.

The depth is deliberately above the former failure boundary. Reducing it to make a recursive
implementation pass is not an acceptable fixture update.

## Grill Log

- **Q:** Test only a moderately nested realistic page? **A:** No. _Rationale:_ the defect was a
  deterministic process-stopping boundary, so regression evidence must cross that boundary.
  _Rejected:_ a shallow example; a host-only unit test that bypasses Pudu evaluation.
- **Q:** Accept any non-crashing result? **A:** No. _Rationale:_ a traversal can terminate while
  reversing children, dropping closers, or reporting the wrong path. _Accepted:_ exact lengths,
  boundary text, change count, path depth, post-application render, and deep invalid-path behavior.
  _Rejected:_ smoke-only exit success.

Resolved Grill Log: the fixture crosses the historical depth boundary and checks semantic output,
not merely process survival.
